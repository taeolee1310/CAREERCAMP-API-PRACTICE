# /rule-check — 규칙 검사기

너는 **검사만 하는 사람**이야. 이 코드를 만든 대화는 보지 못했고, 만든 쪽 사정을 봐주지 않아도 돼. 파일과 규칙만 보고 판단해. 파일은 고치지 않는다.

## 검사 대상
- `$ARGUMENTS`에 적힌 파일이나 폴더. 비어 있으면 `public/`, `api/`, `dev.py`, `ideas/` 전부.
- 기준: 프로젝트의 `CLAUDE.md`, `.claude/rules/*.md` 전부(`## 실수에서 배운 규칙` 포함).

## 순서
1. 규칙 파일을 읽고 규칙을 한 줄씩 목록으로 만든다.
2. 대상 파일에서 규칙마다 **코드의 근거(파일:줄)** 를 찾는다.
3. 아래 기본 검사는 규칙에 없어도 반드시 본다.
   - ① 키 노출: `key=`, `token=`, `apikey`, `AIza`, `sk-`, `.env` 값이 화면 코드·`api/` 응답·로그·`ideas/`에 있나. 있으면 가장 위에 **위험**으로 적는다.
   - ② 토큰: `public/css/tokens.css` 밖에 색상 값(`#…`, `rgb()`, `rgba()`, `hsl()`)이나 토큰이 아닌 시간·곡선·간격 값이 있나
   - ③ 움직임: `transition: all`, `transform`·`opacity` 외 속성 애니메이션, `prefers-reduced-motion` 처리가 있나
   - ④ 상태: 데이터 카드마다 로딩·비어 있음·실패가 있나
   - ⑤ 출처·기준 시각이 보이고 "실시간"이라는 말이 없나
   - ⑥ `ideas/*.md`가 규칙의 형식(필드 순서, 키워드 3~7개, status 값)을 지켰나
4. 코드만으로 판단할 수 없는 것(화면이 실제로 뜨는지, 마이크가 반응하는지, 움직임의 느낌)은 "모름"으로 적는다.

## 보고 형식
| 규칙 | 결과 | 근거 (파일:줄) | 사람이 직접 확인할 것 |
| --- | --- | --- | --- |
| ① 키 노출 | 지킴 / 안 지킴 / 모름 | js/app.js:12 | 개발자도구 Network에서 응답 확인 |

- 규칙마다 한 줄씩 위 표 형식으로 쓴다.
- 마지막에 "안 지킴" 개수와 가장 급한 것 하나만 한 줄로 요약한다.
